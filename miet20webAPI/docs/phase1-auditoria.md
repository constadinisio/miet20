# Fase 1 · Auditoría reforzada de migración a API

## 1. Alcance y módulos analizados
- Se revisaron los dominios funcionales inventariados en la Fase 0 (autenticación multirol, administración académica, SPEI, sitio público y utilidades compartidas) para trazar cómo cada flujo PHP deberá apoyarse en la API.【F:docs/phase0-preparacion.md†L5-L28】
- La auditoría incluye scripts críticos de `backend/`, `public/` y utilidades que todavía consumen `backend/includes/db.php`, identificando si existe ya un endpoint equivalente en `docs/API.md` o si se requiere ampliarlo.【F:backend/includes/db.php†L1-L7】【F:docs/API.md†L1-L206】
- Como output, se definen brechas de funcionalidad, ajustes contractuales y un backlog incremental para comenzar la sustitución módulo por módulo.

## 3. Brechas funcionales y ajustes requeridos
1. **Selección de rol activo y sincronización de sesión**: hoy se modifica en PHP (`cambiar_rol.php`) y se replican permisos vía `$_SESSION`; se debe exponer un endpoint en la API que recalcule permisos y devolver la sesión compacta que consumirá el frontend tras cada cambio de rol.【F:backend/includes/cambiar_rol.php†L1-L33】【F:docs/API.md†L24-L75】
2. **Boletines digitales**: la API debe modelar `reportCards` con calificaciones por materia, observaciones e historial de publicación para reemplazar los formularios de preceptoría (`editar_boletin.php`, `publicar_boletin.php`, `exportar_boletin.php`).【F:backend/users/preceptor/utils/editar_boletin.php†L1-L116】【F:backend/users/preceptor/utils/exportar_boletin.php†L25-L148】
3. **Galería institucional y medios**: migrar consultas `SELECT * FROM imagenes` y filesystem local a un servicio API que gestione categorías, paginación y URLs firmadas, incluyendo endpoints de subida compatibles con los formularios actuales.【F:public/galeria.php†L1-L77】【F:public/galeriaUtils/subirImagenes.php†L1-L80】
4. **Noticias y panel editorial**: sustituir el almacenamiento en JSON e imágenes locales por recursos `news` versionados en la API, respetando permisos `permNoticia` y devolviendo metadatos para la UI.【F:public/panelNoticias/actions/guardarNoticia.php†L1-L56】【F:docs/phase0-preparacion.md†L19-L27】
5. **Registro/autogestión por Google**: encapsular validaciones de datos personales, hash de contraseñas y aprobación administrativa dentro de la API; el frontend solo deberá enviar el payload y manejar estados de aprobación.【F:backend/includes/guardar_registro_google.php†L1-L76】
6. **Asistencias semanales**: ampliar la API para devolver la grilla semanal (columnas por fecha) que actualmente arma `obtener_asistencias_materia.php`, evitando cálculos redundantes en PHP.【F:backend/users/profesor/obtener_asistencias_materia.php†L23-L94】【F:docs/API.md†L206-L214】
7. **Cliente API unificado**: extender `public/includes/apiClient.php` con helpers de dominio (autenticación, cursos, asistencias, noticias, galería, registros) para aislar las vistas de la manipulación directa de tokens y errores, aprovechando la infraestructura de `api_request`.【F:public/includes/apiClient.php†L1-L104】
